API Port de Plaisance Russell

Cette API permet de gérer les catways, les réservations et les utilisateurs du port de plaisance Russell.

Adresse de base

http://localhost:3000

Authentification

Les routes de gestion nécessitent une session utilisateur authentifiée.

Liste des routes

1. Gestion des catways

Ces routes permettent de consulter, ajouter, modifier et supprimer les catways du port. Une authentification est nécessaire.

Méthode Route Description
GET /catways Récupérer tous les catways
GET /catways/:id Récupérer un catway par son numéro
POST /catways Ajouter un nouveau catway
PUT /catways/:id Modifier l'état d'un catway
DELETE /catways/:id Supprimer un catway

Exemple : ajouter un catway

Méthode : POST

Route : /catways

Corps de la requête (JSON) :

{
    "catwayNumber": 25,
    "catwayType": "long",
    "catwayState": "Disponible"
}

Le type de catway doit être long ou short.

2. Gestion des réservations

Ces routes permettent de gérer les réservations associées aux catways du port. Une authentification est nécessaire.

Méthode Route Description
GET /catways/:id/reservations Récupérer les réservations d'un catway
GET /catways/:id/reservations/:idReservation Récupérer une réservation précise
POST /catways/:id/reservations Créer une réservation
PUT /catways/:id/reservations Modifier une réservation
DELETE /catways/:id/reservations/:idReservation Supprimer une réservation

Exemple : ajouter une réservation

Méthode : POST

Route : /catways/1/reservations

Corps de la requête (JSON) :

{
    "clientName": "Jean Dupont",
    "boatName": "Le Neptune",
    "startDate": "2026-11-20",
    "endDate": "2026-11-25"
}

Le paramètre :id correspond au numéro du catway.

Le paramètre :idReservation correspond à l'identifiant MongoDB de la réservation.

Pour modifier une réservation avec PUT, l'identifiant idReservation doit être transmis dans le corps JSON.

3. Gestion des utilisateurs

Ces routes permettent de consulter, créer, modifier et supprimer les utilisateurs. Une authentification est nécessaire.

Méthode Route Description
GET /users Récupérer tous les utilisateurs
GET /users/:email Récupérer un utilisateur par son e-mail
POST /users Créer un utilisateur
PUT /users/:email Modifier un utilisateur
DELETE /users/:email Supprimer un utilisateur

Exemple : ajouter un utilisateur

Méthode : POST

Route : /users

Corps de la requête (JSON) :

{
    "username": "Jean Dupont",
    "email": "jean@example.com",
    "password": "MotDePasse123!"
}

Le mot de passe doit contenir au minimum 8 caractères.

Les mots de passe sont hachés avec bcrypt avant leur enregistrement dans MongoDB.

Le paramètre :email correspond à l'adresse e-mail de l'utilisateur.

4. Authentification

L'API utilise express-session pour gérer les sessions des utilisateurs.

Méthode Route Description
POST /login Connecter un utilisateur
GET /logout Déconnecter un utilisateur
GET /me Récupérer les informations de l'utilisateur connecté

Exemple : connexion

Méthode : POST

Route : /login

Corps de la requête (JSON) :

{
    "email": "admin@russell.fr",
    "password": "VOTRE_MOT_DE_PASSE"
}

Si les identifiants sont corrects, une session utilisateur est créée.

Déconnexion

La route GET /logout détruit la session de l'utilisateur.

Protection des routes

Les routes de gestion des catways, réservations et utilisateurs sont protégées par le middleware requireAuth.

Si un utilisateur non connecté tente d'accéder à une route protégée, l'API renvoie une erreur HTTP 401.
